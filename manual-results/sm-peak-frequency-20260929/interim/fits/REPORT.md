# 每个 SM 峰值功耗与频率拟合

功耗来自 `lyhong_power_report.log` 的 SM_0…SM_79 列：每列取所有采样窗口的最大值。SM 列按现有实现包含 SM 内各模块、流水线和空闲功耗，未分摊 GPU 全局静态功耗及其他非 SM 项。不是 GPU 总功耗，也不是瞬时峰值。窗口固定为 500 个核心周期，频率变化时对应的实际窗口时间变化。

Core、ICNT、L2 同频，DRAM 固定 850 MHz，关闭 DVFS、保持电压配置。单 benchmark 可使用全部 80 SM；混合 benchmark 是已有 43/9/28 SM 分配，另列为独立条件。

频率点：800、1132、1400、1698、2200、2800、3396、4000 MHz。1400 和 2800 MHz 留出验证；其余六点通过留一交叉验证选模型，最终系数用全部八点重新拟合。CV RMSE 相差不超过 0.002 W 时选参数更少的模型。拟合只适用于该区间与该 trace/调度条件。

共 11 个负载条件，外加跨负载峰值包络，共 960 条 SM 曲线。模型数量：`{'constant': 173, 'affine': 464, 'quadratic': 146, 'cubic': 111, 'offset_f_cubed': 66}`。

拟合曲线不保证始终高于观测峰值，也不保证对未采样频率构成上界。

模型公式与逐 SM 系数见 models.json / models.csv，全部候选模型的验证结果见 candidate_validation.csv。频率 f 的单位为 GHz，P 的单位为 W。constant 表示本次观测无法辨认频率依赖，不意味着 SM 在其他负载下恒定功耗。

envelope_all_sampled_conditions 进一步在每个频率、每个 SM 上取所有负载条件的最大值，来源记录在 sm_peak_envelope.csv。它只覆盖已采样的 traces，不能保证覆盖其他输入规模、SM 分配或所有潜在负载。

每个 SM 的峰值可能发生在不同时间，80 个峰值拼成的向量不是同时发生的功耗快照。用于稳态热分析时只能解释为给定采样条件下的逐块峰值包络场景；不能把它直接当作实测稳态功耗。功耗日志通常保留三位小数，尾部不足一个窗口的活动未必进入报告。
